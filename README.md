# Мониторинг техники (ЕТС)

Система мониторинга коммунальной техники ГБУ «Жилищник» (район Тропарёво-Никулино).
Собирает данные из ЕТС, анализирует треки, связь БНСО и топливо, показывает результат
в таблице с картой и помогает формировать заявки на ремонт в ЕСТП.

---

## Возможности

### Сбор данных
- Авторизация в ЕТС с сохранёнными учётными данными.
- Выгрузка журнала заданий за выбранную дату (до 100 строк).
- Перехват WebSocket-потока для отслеживания связи БНСО в реальном времени.
- Сопоставление госномеров с GPS-кодами и гаражными номерами через `car_actual`.
- Параллельная загрузка треков за сутки (батчами по 10).
- Извлечение датчиков топлива (старт, финиш, заправка) из ответа ЕТС.

### Анализ
- **БНСО**: предупреждение после 2 ч молчания, сбой — после 4 ч.
- **Трек**: доля валидных точек, минимальный порог для анализа.
- **Телепорты**: скачки > 200 км/ч или > 30 км за < 5 мин.
- **Пробег**: сумма расстояний без телепортов.
- **Фейковые координаты**: последняя точка > 60 км от базы при медиане < 60 км.
- **Выезд с базы**: время и расстояние вне радиуса 5 км от базы.
- **Классификация**: `Норма`, `Некорректное местоположение ТС`, `Некорректный трек`, `Машина не на связи`, `Не работает БНСО`.

### GUI (PyQt6)
- Таблица: номер, марка, задание, % выполнения, топливо, пробег, статус, детали.
- Цветовая индикация проблем.
- Поиск и фильтрация, сортировка, экспорт в CSV, копирование (Ctrl+C).
- Выбор даты проверки, автообновление каждые 5 минут.
- Встроенная карта Leaflet (справа от таблицы).
- Отрисовка трека выбранной машины по клику на строку.
- Кнопка «Сформировать заявки в ЕСТП» (dry-run: заполняет форму, не отправляет).

### ЕСТП
- Автозаполнение формы заявки (Playwright, headless=False).
- Тип заявки выбирается по проблеме:
  - `Некорректный трек ТС` — при проблемах с треком/местоположением.
  - `Проведение работ по восстановлению неработающего БНСО` — при отсутствии связи.
- Окно остаётся открытым 60 секунд для проверки перед отправкой.

Как это работает
Сбор данных
Логин в ЕТС -> Playwright, headless.

Карта -> перехват WebSocket (ets_stream.py) + ответов car_actual.

Журнал заданий -> переключение на 100 строк, выгрузка миссий за дату.

Сопоставление car_id -> gps_code -> gov_number.

Треки — параллельно, батчами по 10, через page.request.get с токеном из localStorage.

Кэш связи — cache.json для машин без timestamp в WS.

Анализ
Для каждой машины:

Связь (БНСО) — последний timestamp из WS или кэша.

Трек — фильтрация валидных точек (coords != [0,0], is_valid != false).

Топливо — из корня ответа: sensor_start_value, sensor_finish_value, sensor_refill.

Телепорты — проверка каждой пары соседних точек.

Пробег — сумма без телепортов.

Проверка «фейка» — последняя точка > 60 км от базы при медиане < 60 км.

Выезд с базы — время и расстояние вне радиуса 5 км.

Классификация — по приоритету: фейк -> низкая валидность -> нет трека -> телепорты -> БНСО -> норма.

Отрисовка трека
Клик по строке -> cars_data[row]['_track_raw'] -> window.drawTrack(coords, carNumber) в Leaflet -> polyline + маркер последней точки + fitBounds.

Наследие
До Мониторинга было два отдельных проекта, чьи исходники лежат в legacy/:

legacy/map/ — карта-редактор улиц, дворов и маршрутов (Vite + Leaflet + Geoman) и Node-прототип бота ЕТС. Не используется Мониторингом, оставлен для истории.

legacy/bot/ — старые парсеры ЕТС (parse_ets.py, parse_all_routes.py, parse_geozones.py) и выгруженные ими данные (ets_*.json). НСлужат запчастями: содержат полезные скрипты для разового парсинга данных, которые можно адаптировать под текущие задачи.

Подробности — в legacy/README.md. Обе папки можно удалить без вреда для Мониторинга.

Известные проблемы
radio_bnso не существует — gui.py -> create_tickets() ссылается на self.radio_bnso, которого нет. Кнопка «Просмотр заявок для выбранных машин» упадёт при клике.

cars_data[row] после сортировки — gui.py -> on_row_selected() берёт self.cars_data[row], но после сортировки таблицы индекс строки не равен индексу в списке. Трек может рисоваться не для той машины.

Двойной блок парсинга топлива — в bot_worker.py блок парсинга fuel_* дублируется в конце; работает случайно (через ссылку на объект), но хрупко.

Кракозябры в estp_worker.py — комментарии в кодировке не UTF-8; на работу не влияет, но читать невозможно.

Все четыре — в очереди на исправление.
