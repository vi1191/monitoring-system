# Мониторинг техники (ЕТС)

Система мониторинга коммунальной техники ГБУ «Жилищник» (район Тропарёво-Никулино).
Собирает данные из ЕТС, анализирует треки, связь БНСО и топливо, показывает результат
в таблице с картой и помогает формировать заявки на ремонт в ЕСТП.

---

## Возможности

### Сбор данных
- Авторизация в ЕТС с сохранёнными учётными данными.
- **Выгрузка всех миссий за выбранную дату через прямой запрос к API** (без ограничения в 100 строк и без кликов по пагинации).
- Перехват WebSocket-потока для отслеживания связи БНСО в реальном времени.
- Сопоставление госномеров с GPS-кодами и гаражными номерами через `car_actual`.
- **Параллельная загрузка треков** (батчами по 10 через `requests`, потокобезопасно) — ускоряет сбор с ~5 минут до ~1 минуты.
- Извлечение датчиков топлива (старт, финиш, заправка) из ответа ЕТС.

### Анализ
- **Классификация по 3 критериям:**
  1. **Срыв (Красный):** В треке есть телепорты (зигзаги, скачки > 1 км за < 10 мин), GPS-сбой или машина уехала дальше 20 км от базы.
  2. **Нет трека (Оранжевый):** Связь (БНСО) есть, но точек меньше 50 (трек не пишется).
  3. **Нет связи (Серый):** Машина молчит более 4 часов.
  4. **Норма (Зеленый):** Все остальные случаи.
- **Телепорты**: скачки > 100 км/ч или > 2 км за короткое время (настраивается).
- **Пробег**: сумма расстояний без телепортов.
- **Фейковые координаты**: если точка улетела дальше 100 км от базы.
- **Фильтрация по дате**: бот запрашивает миссии за указанный день и показывает только те машины, у которых была активная миссия в этот день.

### GUI (PyQt6)
- Таблица: номер, марка, задание (с номером факсограммы, если есть), % выполнения, топливо (3 колонки), пробег, статус, детали.
- Цветовая индикация проблем (красный, оранжевый, серый, зеленый).
- Поиск и фильтрация, сортировка, экспорт в CSV, копирование (Ctrl+C).
- Выбор даты проверки.
- Встроенная карта Leaflet (справа от таблицы).
- Отрисовка трека выбранной машины по клику на строку.
- **Скрытие трека при двойном клике на строку**.
- **Кастомная кнопка-«глаз» в левом нижнем углу карты** для плавного скрытия/показа слоя дорог.
- **Окно подтверждения заявок**: перед отправкой в ЕСТП вы видите список выбранных машин, можете выбрать классификацию обращения из списка ЕСТП, а также выбрать шаблон комментария (с автодополнением) или написать свой текст.

### ЕСТП (API-режим)
- **Отправка заявок без открытия окон браузера** (работает в фоне).
- Автоматическая авторизация, выбор организации «Жилищник Тропарево-Никулино».
- Поиск машины по госномеру для получения внутреннего ID.
- Извлечение CSRF-токена для защиты от подделки запросов.
- Отправка POST-запроса через `page.request.post` (в 10 раз быстрее кликов).
- Проверка ответа сервера (JSON) на наличие ошибок.

Как это работает
Сбор данных
Логин в ЕТС -> Playwright, headless.

Карта -> перехват WebSocket (ets_stream.py) + ответов car_actual.

Журнал заданий -> прямой запрос к API /services/mission с фильтром по дате.

Сопоставление car_id -> gps_code -> gov_number.

Треки — параллельно, батчами по 10, через requests.get, токен берется из localStorage.

Кэш связи — cache.json для машин без timestamp в WS.

Анализ
Для каждой машины:

Связь (БНСО) — последний timestamp из WS или кэша.

Трек — фильтрация валидных точек.

Топливо — из корня ответа.

Телепорты — проверка каждой пары соседних точек.

Пробег — сумма без телепортов.

Проверка «фейка» — последняя точка > 100 км от базы.

Выезд с базы — время и расстояние вне радиуса.

Классификация — по 3 критериям (срыв, нет трека, нет связи, норма).

Отправка заявок в ЕСТП (API-режим)
Вы ставите галочки на машины и нажимаете «Создать заявки в ЕСТП».

Открывается окно, где для каждой машины можно выбрать классификацию и отредактировать текст комментария.

После нажатия «ОТПРАВИТЬ В ЕСТП» бот (в фоне):

Запускает Playwright в headless режиме.

Логинится, выбирает организацию «Жилищник Тропарево-Никулино».

Ищет машину по номеру, получает её ID.

Извлекает CSRF-токен из HTML.

Отправляет POST-запрос через page.request.post на /index.php?r=telemetry/create-estp-request.

Проверяет ответ (JSON) и выводит статус в консоль.

Наследие
До Мониторинга было два отдельных проекта, чьи исходники лежат в legacy/:

legacy/map/ — карта-редактор улиц, дворов и маршрутов (Vite + Leaflet + Geoman) и Node-прототип бота ЕТС. Не используется Мониторингом, оставлен для истории.

legacy/bot/ — старые парсеры ЕТС (parse_ets.py, parse_all_routes.py, parse_geozones.py) и выгруженные ими данные (ets_*.json). Служат запчастями: содержат полезные скрипты для разового парсинга данных, которые можно адаптировать под текущие задачи.

Подробности — в legacy/README.md. Обе папки можно удалить без вреда для Мониторинга.

Известные проблемы
Кракозябры в estp_worker.py — комментарии в кодировке не UTF-8; на работу не влияет, но читать невозможно. (В очереди на исправление).
